# Alteração da Software Factory — Gestão de Sistemas, Artefatos e Especificação Assistida

## 1. Objetivo

Evoluir a Software Factory para permitir o gerenciamento dos sistemas existentes, seus respectivos artefatos técnicos e a associação desses sistemas aos clientes.

A funcionalidade de Especificação Assistida — SPEC deverá utilizar essas informações para identificar quais sistemas e artefatos serão impactados por uma determinada demanda.

Nesta evolução, a geração da especificação não deverá mais chamar diretamente uma API de LLM.

A Software Factory deverá reunir as informações disponíveis da demanda e gerar um **prompt inicial estruturado**, que poderá ser copiado pelo Analista e utilizado manualmente em uma IA de sua preferência, como ChatGPT, Claude, Gemini ou outra ferramenta compatível.

---

# 2. Escopo

A alteração contempla:

1. Cadastro e manutenção de Sistemas.
2. Cadastro e manutenção dos Artefatos pertencentes a cada Sistema.
3. Associação de múltiplos Sistemas a um Cliente.
4. Seleção dos Sistemas envolvidos em uma demanda na Especificação Assistida — SPEC.
5. Seleção dos Artefatos que serão trabalhados na demanda.
6. Restrição dos Sistemas disponíveis conforme os Sistemas associados ao Cliente.
7. Desabilitação do botão "Enviar para IA".
8. Criação da funcionalidade "Gerar Prompt SPEC".
9. Consolidação automática das informações da demanda em um prompt.
10. Disponibilização do prompt para visualização e cópia.
11. Utilização do arquivo `prompt-spec-kit.md` como modelo do prompt gerado.

---

# 3. Conceitos

## 3.1 Sistema

Representa um produto ou aplicação existente dentro da organização.

Exemplos:

- Vexur
- Sistema de Gestão de Clientes
- Sistema Financeiro

Um Sistema pode possuir diversos Artefatos.

---

## 3.2 Artefato

Representa uma unidade técnica pertencente a um Sistema e que pode ser impactada por uma demanda.

Exemplos:

- Frontend
- API
- Serviço
- Banco de Dados
- Worker
- Microserviço
- Biblioteca

Cada Artefato deverá possuir, no mínimo:

- Nome
- Tipo
- Tecnologia
- Sistema ao qual pertence

### Exemplo

Sistema:

```text
Vexur
```

Artefatos:

```text
vexur-operacao-contrato-adesao
Tipo: Tela
Tecnologia: Vue 2.0
```

```text
api-vexur-operacao-contrato-adesao
Tipo: API
Tecnologia: Node.js / Express
```

---

# 4. Cadastro de Sistemas

Criar uma nova tela de manutenção denominada:

**Sistemas**

A tela deverá permitir:

- Listar Sistemas.
- Criar Sistema.
- Alterar Sistema.
- Ativar/Inativar Sistema.
- Visualizar os Artefatos pertencentes ao Sistema.
- Criar Artefatos.
- Alterar Artefatos.
- Ativar/Inativar Artefatos.

## 4.1 Dados do Sistema

O Sistema deverá possuir:

- ID
- Nome
- Descrição
- Status ativo/inativo
- Data de criação
- Data de atualização

---

# 5. Cadastro de Artefatos

Cada Sistema poderá possuir vários Artefatos.

Um Artefato deverá possuir:

- ID
- Sistema
- Nome
- Tipo
- Tecnologia
- Descrição
- Status ativo/inativo
- Data de criação
- Data de atualização

## 5.1 Tipos de Artefato

O sistema deverá permitir tipos como:

- Tela
- API
- Serviço
- Worker
- Banco de Dados
- Microserviço
- Biblioteca
- Componente
- Outro

A solução deverá permitir evolução desses tipos posteriormente.

## 5.2 Exemplo

```text
Sistema: Vexur

Artefato:
Nome: vexur-operacao-contrato-adesao
Tipo: Tela
Tecnologia: Vue 2.0

Artefato:
Nome: api-vexur-operacao-contrato-adesao
Tipo: API
Tecnologia: Node.js / Express
```

---

# 6. Associação de Sistemas aos Clientes

Alterar a Tela de Clientes para permitir associar um ou mais Sistemas ao Cliente.

Um Cliente poderá possuir:

```text
Cliente A
 ├── Sistema Vexur
 ├── Sistema Financeiro
 └── Sistema RH
```

Portanto, a relação entre Cliente e Sistema deverá ser **N:N**.

Um Cliente pode possuir vários Sistemas.

Um Sistema pode estar associado a vários Clientes.

## 6.1 Regras

Somente Sistemas ativos deverão estar disponíveis para associação.

Um Sistema não poderá ser associado duas vezes ao mesmo Cliente.

A remoção da associação não deverá excluir fisicamente o Sistema nem o Cliente.

---

# 7. Especificação Assistida — SPEC

A Tela de Especificação Assistida — SPEC deverá ser modificada para permitir informar quais Sistemas serão envolvidos na demanda.

## 7.1 Sistemas disponíveis

Ao criar ou editar uma especificação, o sistema deverá apresentar somente os Sistemas associados ao Cliente da demanda.

Exemplo:

```text
Cliente: Empresa ABC

Sistemas associados:
[x] Vexur
[x] Financeiro
[ ] RH
```

Se o Cliente possuir apenas o Sistema Vexur, somente Vexur deverá ser disponibilizado.

---

# 8. Seleção de Artefatos

Após selecionar um Sistema, a tela deverá apresentar os Artefatos ativos pertencentes ao Sistema.

Exemplo:

```text
Sistema: Vexur

Artefatos:

[x] vexur-operacao-contrato-adesao
    Tipo: Tela
    Tecnologia: Vue 2.0

[x] api-vexur-operacao-contrato-adesao
    Tipo: API
    Tecnologia: Node.js / Express
```

O Analista deverá poder selecionar um ou mais Artefatos.

Uma demanda poderá envolver:

- Um Sistema e um Artefato.
- Um Sistema e vários Artefatos.
- Vários Sistemas e vários Artefatos.

---

# 9. Regras da Especificação

A especificação deverá manter a seguinte estrutura conceitual:

```text
Demanda
 ├── Cliente
 ├── Informações de negócio
 ├── Insumos técnicos
 ├── Sistemas envolvidos
 │    ├── Sistema
 │    │    └── Artefatos envolvidos
 │    └── Sistema
 │         └── Artefatos envolvidos
 └── Demais informações da demanda
```

Os Sistemas e Artefatos selecionados deverão fazer parte das informações utilizadas na geração do prompt.

---

# 10. Desabilitação da integração direta com IA

Na Tela de Especificação Assistida — SPEC, o botão:

```text
Enviar para IA
```

deverá ser desabilitado/removido da operação.

Nesta versão, a Software Factory **não deverá realizar chamadas para APIs de LLM para gerar a especificação**.

A responsabilidade pela interação com a IA passará a ser do Analista.

---

# 11. Geração do Prompt SPEC

Adicionar uma nova funcionalidade:

```text
Gerar Prompt SPEC
```

Essa funcionalidade deverá:

1. Obter as informações da demanda.
2. Obter as informações de negócio.
3. Obter os insumos técnicos.
4. Obter os Sistemas envolvidos.
5. Obter os Artefatos envolvidos.
6. Consolidar essas informações.
7. Utilizar o modelo `prompt-spec-kit.md`.
8. Gerar um prompt completo.
9. Disponibilizar o conteúdo para visualização.
10. Permitir copiar o conteúdo.

---

# 12. Prompt gerado

O prompt deverá ser estruturado para que o Analista possa copiar seu conteúdo e colá-lo manualmente em uma IA de sua preferência.

Exemplo conceitual:

```text
CONTEXTO DA DEMANDA

[descrição da demanda]

INFORMAÇÕES DE NEGÓCIO

[informações de negócio]

INSUMOS TÉCNICOS

[insumos técnicos]

SISTEMAS ENVOLVIDOS

Sistema: Vexur

ARTEFATOS ENVOLVIDOS

- vexur-operacao-contrato-adesao
  Tipo: Tela
  Tecnologia: Vue 2.0

- api-vexur-operacao-contrato-adesao
  Tipo: API
  Tecnologia: Node.js / Express

INSTRUÇÕES

Utilize as informações acima para analisar a demanda e produzir
uma especificação estruturada seguindo as orientações do SPEC Kit.
```

O conteúdo final deverá ser baseado no arquivo:

```text
prompt-spec-kit.md
```

Esse arquivo deverá funcionar como **template oficial do prompt utilizado pela Software Factory**.

---

# 13. Copiar Prompt

Após a geração, o sistema deverá disponibilizar o prompt em uma área de texto ou editor apropriado.

Deverá existir uma ação:

```text
Copiar Prompt
```

O conteúdo copiado deverá ser exatamente o prompt gerado.

O Analista poderá então colar o conteúdo em:

- ChatGPT
- Claude
- Gemini
- Outra IA de preferência

---

# 14. Persistência

A seleção dos Sistemas e Artefatos deverá ser persistida junto à demanda/especificação.

Isso permitirá posteriormente:

- Consultar quais Sistemas foram envolvidos.
- Consultar quais Artefatos foram impactados.
- Reutilizar essas informações.
- Gerar novamente o prompt.
- Utilizar essas informações em etapas futuras do processo de desenvolvimento.

---

# 15. Auditoria

As operações relevantes deverão gerar registro de log/auditoria.

Devem ser consideradas, no mínimo:

- Criação de Sistema.
- Alteração de Sistema.
- Ativação/Inativação de Sistema.
- Criação de Artefato.
- Alteração de Artefato.
- Ativação/Inativação de Artefato.
- Associação Sistema/Cliente.
- Remoção da associação Sistema/Cliente.
- Seleção de Sistema em uma demanda.
- Seleção de Artefato em uma demanda.
- Geração do Prompt SPEC.

---

# 16. Critérios de Aceite

### CA01 — Sistema

Dado que o usuário possui permissão para manutenção de Sistemas,

Quando acessar a tela de Sistemas,

Então deverá conseguir cadastrar, alterar, ativar e inativar Sistemas.

### CA02 — Artefatos

Dado um Sistema existente,

Quando acessar seus Artefatos,

Então deverá conseguir cadastrar e manter os Artefatos daquele Sistema.

### CA03 — Cliente

Dado um Cliente,

Quando acessar sua manutenção,

Então deverá conseguir associar um ou mais Sistemas ao Cliente.

### CA04 — Restrição de Sistemas

Dado um Cliente com Sistemas associados,

Quando criar uma especificação,

Então somente os Sistemas associados ao Cliente deverão estar disponíveis.

### CA05 — Artefatos

Dado um Sistema selecionado na especificação,

Quando o usuário selecionar o Sistema,

Então os Artefatos ativos pertencentes a esse Sistema deverão ser disponibilizados para seleção.

### CA06 — Múltiplos Sistemas

Dado que um Cliente possui vários Sistemas,

Quando criar uma especificação,

Então o usuário poderá selecionar mais de um Sistema.

### CA07 — Múltiplos Artefatos

Dado que um Sistema possui vários Artefatos,

Quando o Sistema estiver selecionado,

Então o usuário poderá selecionar vários Artefatos.

### CA08 — IA

O sistema não deverá realizar chamada direta para uma API de LLM através da funcionalidade SPEC.

### CA09 — Prompt

Dado que uma demanda possui informações preenchidas,

Quando o usuário selecionar "Gerar Prompt SPEC",

Então o sistema deverá gerar um prompt utilizando o modelo `prompt-spec-kit.md`.

### CA10 — Copiar

Dado que o prompt foi gerado,

Quando o usuário selecionar "Copiar Prompt",

Então o conteúdo completo deverá ser copiado para a área de transferência.

### CA11 — Rastreabilidade

O prompt deverá conter os Sistemas e Artefatos selecionados para a demanda.

---

# 17. Fora do escopo

Não faz parte desta alteração:

- Chamada de API de LLM.
- Escolha automática da IA pelo sistema.
- Execução automática do `/speckit.specify`.
- Execução automática do `/speckit.plan`.
- Geração automática de código.
- Integração direta com ChatGPT, Claude ou Gemini.
- Exclusão física de registros.
