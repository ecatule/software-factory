# Plano de Implementação — Gestão de Sistemas, Artefatos e SPEC

## 1. Objetivo Técnico

Implementar as alterações descritas na especificação funcional, incorporando:

- Gestão de Sistemas.
- Gestão de Artefatos.
- Associação Cliente x Sistema.
- Associação Demanda/Especificação x Sistema.
- Associação Demanda/Especificação x Artefato.
- Geração de Prompt SPEC.
- Remoção/desabilitação da chamada direta de LLM na etapa SPEC.

A implementação deverá preservar os padrões arquiteturais existentes da Software Factory.

---

# 2. Arquitetura

A implementação deverá respeitar a arquitetura atual do projeto:

```text
MONOREPO
│
├── frontend
│   └── React + TypeScript
│
├── backend
│   └── Node.js + TypeScript
│
└── database
    └── PostgreSQL
```

A comunicação entre frontend e backend deverá ocorrer através de API REST.

O backend deverá ser responsável pelas regras de negócio e autorização.

---

Campos sugeridos:


Regras:

- `nome` obrigatório.
- `st_ativo` deve permitir ativação/inativação.

# 4. Tabela `artefatos`

Criar tabela para representar os Artefatos.

Campos sugeridos:

```text
id
sistema_id
nome
tipo
tecnologia
descricao
st_ativo
created_at
updated_at
```

Relacionamento:

```text
sistemas 1 ---- N artefatos
```

Regras:

- `sistema_id` obrigatório.
- Artefato deve pertencer a um Sistema.
- Não permitir Artefato ativo associado a Sistema inativo.
- Não realizar exclusão física.
- `nome` obrigatório.
- `tipo` obrigatório.
- `tecnologia` poderá ser obrigatória conforme regra definida pelo domínio.

# 8. Integridade dos Artefatos selecionados

O backend deverá validar que um Artefato selecionado pertence a um Sistema que também foi selecionado para aquela demanda.

Exemplo inválido:

```text
Demanda
 └── Sistema: Vexur

Artefato selecionado:
 └── api-sistema-financeiro
```

Essa operação deverá ser rejeitada.

Também deverá ser validado que:

```text
Artefato
    ↓
Sistema
    ↓
Cliente
```

Ou seja, o Sistema associado ao Artefato deverá estar associado ao Cliente da demanda.

# 12. Demanda x Sistemas

```json
    {
      "sistemaId": "..."
    }
  ]
```

O backend deverá validar se os Sistemas pertencem ao Cliente da demanda.

# 13. Demanda x Artefatos


Exemplo:

1. Artefato existe.
2. Artefato está ativo.
3. Artefato pertence a um Sistema selecionado.

# 16. Regra de carregamento

A tela SPEC não deverá carregar todos os Sistemas existentes.

Deverá consultar:

```text
Cliente
   ↓
Sistemas associados
   ↓
Sistemas ativos
```

Somente esses Sistemas poderão ser selecionados.

Após selecionar o Sistema:

```text
Sistema
   ↓
Artefatos ativos
```

# 17. Geração do Prompt

Criar endpoint específico para geração do prompt.

Sugestão:

```http
GET /demandas/:demandaId/prompt-spec
```

ou:

```http
POST /demandas/:demandaId/prompt-spec
```

Preferencialmente utilizar `POST` caso a geração seja considerada uma operação de processamento.

O backend deverá:

1. Carregar a demanda.
2. Carregar informações de negócio.
3. Carregar insumos técnicos.
4. Carregar Cliente.
5. Carregar Sistemas selecionados.
6. Carregar Artefatos selecionados.
7. Carregar o template `prompt-spec-kit.md`.
8. Realizar a substituição das variáveis.
9. Retornar o prompt final.

---

# 18. Template `prompt-spec-kit.md`

O template deverá ficar centralizado e versionado.

Sugestão:

```text
/config/prompts/prompt-spec-kit.md
```

ou estrutura equivalente adotada pelo projeto.

O template deverá possuir marcadores claros para substituição.

Exemplo:

```text
# CONTEXTO DA DEMANDA

{{demanda.descricao}}

# INFORMAÇÕES DE NEGÓCIO

{{demanda.informacoes_negocio}}

# INSUMOS TÉCNICOS

{{demanda.insumos_tecnicos}}

# CLIENTE

{{cliente.nome}}

# SISTEMAS ENVOLVIDOS

{{sistemas}}

# ARTEFATOS ENVOLVIDOS

{{artefatos}}

# INSTRUÇÕES

{{instrucoes}}
```

O mecanismo de template deverá ser simples e previsível.

Não é necessário utilizar uma biblioteca complexa se uma substituição controlada de placeholders atender ao requisito.

```text
   ↓

   ↓
```

# 22. Remoção da dependência da LLM

A geração do Prompt SPEC não deverá depender de:

- OpenAI
- Anthropic
- Google Gemini
- Qualquer outro provedor de LLM

O backend deverá ser capaz de gerar o prompt sem realizar qualquer chamada externa de IA.

Isso permite que a Software Factory permaneça independente do provedor de IA utilizado pelo Analista.

```text

```

# 30. Decisões arquiteturais

## DA01 — Sem chamada de LLM

A Software Factory não será responsável pela execução da IA na etapa SPEC.

Responsabilidade:

```text
Software Factory
    ↓
Organiza contexto
    ↓
Gera Prompt
    ↓
Analista copia
    ↓
IA escolhida pelo Analista
```

---

## DA02 — Prompt versionado

O arquivo:

```text
prompt-spec-kit.md
```

será considerado parte do código/configuração da Software Factory e deverá ser versionado no repositório.

Alterações no comportamento do prompt deverão passar pelo mesmo processo de versionamento do código.

---

## DA03 — Sistemas e Artefatos como catálogo

Sistemas e Artefatos deverão funcionar como um catálogo técnico reutilizável.

Eles não deverão existir exclusivamente dentro de uma demanda.

Uma mesma definição poderá ser utilizada em várias demandas.

---

## DA04 — Cliente restringe contexto

O Cliente determina quais Sistemas podem ser utilizados em uma demanda.

Regra:

```text
Cliente
   ↓
Sistemas permitidos
   ↓
Demanda
   ↓
Artefatos dos Sistemas
```

O frontend poderá filtrar as opções, mas o backend deverá obrigatoriamente validar essa regra.

---

# 31. Critério final de conclusão

A implementação será considerada concluída quando for possível executar o fluxo completo:

```text
Cadastrar Sistema
        ↓
Cadastrar Artefatos
        ↓
Associar Sistema ao Cliente
        ↓
Criar Demanda
        ↓
Abrir Especificação Assistida
        ↓
Visualizar somente Sistemas do Cliente
        ↓
Selecionar Sistemas
        ↓
Selecionar Artefatos
        ↓
Gerar Prompt SPEC
        ↓
Visualizar Prompt
        ↓
Copiar Prompt
        ↓
Colar em uma IA externa
```

E estiver garantido que:

```text
❌ Software Factory → LLM
```

não ocorre mais durante essa etapa.

O novo fluxo deverá ser:

```text
Software Factory
      │
      ├── Dados de negócio
      ├── Dados técnicos
      ├── Sistemas
      ├── Artefatos
      │
      ▼
prompt-spec-kit.md
      │
      ▼
Prompt final
      │
      ▼
Analista
      │
      ▼
IA de preferência
```
